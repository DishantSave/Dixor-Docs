Changelog

All notable changes to the Dixor Ecosystem are documented in this file.

The format is based on Keep a Changelog, and this project adheres strictly to Semantic Versioning.

[2026-11-22] — Dixor.Validation [v0.1.1]

Added

  • International Phone & Contact Validation: Comprehensive E.164 phone number formatting, carrier/circle metadata detection, line classification, and contact equality comparison (PhoneValidator, ContactValidator).
  • Passport Verification (ICAO Doc 9303): Machine-readable travel document validation for 60+ countries with date-of-birth, expiry, and 6-month validity rules (PassportValidator).
  • Address & Postal Code Validation: ISO 3166-1 alpha-2/3 country codes, ISO 3166-2 state/province subdivisions, and postal/ZIP code format validation (AddressValidator).
  • Aadhaar Identity Validation: Indian 12-digit UIDAI identity number validation powered by the dihedral group \(D_5\) Verhoeff checksum algorithm and privacy masking (AadhaarValidator).
  • Payment Card Validation: High-speed Luhn mod-10 checksum calculation, IIN/BIN network classification across 10 major global brands (Visa, Mastercard, Amex, Discover, RuPay, etc.), CVV/expiry checking, and PCI-DSS masking (CreditCardValidator).
  • URL/URI Validation with SSRF Defense: RFC 3986 compliant URI syntax parsing with protection against SSRF attacks (blocking localhost, IPv4/IPv6 private subnets, and AWS/cloud metadata) (UrlValidator).
  • Dixor.DI Integration: 1-line registration via services.AddDixorValidation().

[2026-11-22] — Dixor.Identity [v0.2.1]

Changed

  • Internal Dependency Injection: Optimized internal service registration and streamlined instantiation for ULID, Base36, Base62, Hexadecimal, NanoId, NumericCode, Sequence, and ShortId.
  • DI Ecosystem Integration: Seamless 1-line DI registration via services.AddDixorIdentity().
  • Documentation & Metadata: Enhanced XML documentation and NuGet package metadata for .NET 8, 9, and 10 multi-targeting.

[2026-11-22] — Dixor.DI [v0.1.0] (Initial Release)

Added

  • Declarative Service Registration: Custom attributes ([Singleton], [Scoped], [Transient]) for automatic assembly scanning and registration.
  • Modular Architecture: Support for IDixorModule modular registration in multi-project solutions.
  • Unified Ecosystem Bootstrapping: 1-line registration builder.Services.AddDixor() bootstrapping DI, Identity, Security, and Validation services in one call.

[2026-11-22] — Dixor.Security [v0.1.0] & Dixor.Studio

Fixed

  • Universal Cross-Platform AEAD: Resolved PlatformNotSupportedException: Cryptography_AlgorithmNotSupported, Aes across Blazor WebAssembly and browser runtimes. Engineered a pure C# managed AES engine (ManagedAes) supporting standard AES (FIPS 197), AES-CBC with PKCS7 padding, and AES-GCM (NIST SP 800-38D) AEAD encryption.
  • Deterministic Hashing Contrast: Fixed low-contrast styling in Dixor.Studio Deterministic Hashing view where text blended into the background. Engineered a solid slate theme-proof container (#0f172a with #38bdf8 bold text) guaranteeing >10:1 AAA contrast in both light and dark modes.

Added

  • Modular Security Studio: Refactored Dixor.Security within Dixor.Studio into dedicated feature pages:
    • /security/overview — Suite directory & architecture summary
    • /security/auth-tokens — Reversible AES-256 tokens with claims
    • /security/client-credentials — API credentials, RSA 2048/4096 & ECDSA P-256 keys, and digital signing
    • /security/oauth2 — RFC 6749 OAuth2 Bearer token issuance & validation
    • /security/data-encryption — Authenticated AEAD symmetric encryption & decryption
    • /security/deterministic-hashing — One-way keyed blind indexing with determinism verification
    • /security/password-hashing — PBKDF2-SHA256 salted password hashing
    • /security/totp — RFC 6238 2FA authenticator with countdown timer
    • /security/api-keys — CSPRNG API keys with SHA-256 hash digests
    • /security/masking — Sensitive data masking for PCI-DSS & GDPR compliance

[2026-07-23] — Dixor.Identity [v0.2.0]

Added

  • Base36 Identifier Generation (Base36): Introduced a cryptographically secure Base36 string generation API (Base36.Generate()) utilizing numeric characters (0–9) and uppercase alphabetic characters (A–Z). Features optimized stack allocation (stackalloc) for paths up to 256 characters to eliminate heap garbage collection pressure.
  • Base62 Identifier Generation (Base62): Added high-density, URL-safe, and case-sensitive identifier generation (Base62.Generate()) incorporating lowercase alphabetic characters (a–z) alongside numeric digits and uppercase letters for superior information packing density.
  • Hexadecimal Identifier Generation (Hexadecimal): Implemented secure binary-to-hexadecimal encoding (Hexadecimal.Generate()) supporting custom byte counts and configurable uppercase or lowercase case-normalization via optimized .NET routines (Convert.ToHexString).
  • NanoId Generation (NanoId): Added compact, URL-friendly identifier generation (NanoId.Generate()) adapted from the reference Nano ID algorithm. Implements bitmask optimization (BitOperations.Log2) and secure rejection sampling to guarantee strict statistical uniformity without byte bias.
  • Numeric Code Generation (NumericCode): Introduced digits-only code generation (NumericCode.Generate()) restricted to numbers (0–9), specifically optimized for verification codes, multi-factor authentication (MFA), and one-time passwords (OTPs).
  • Thread-Safe Integer Sequences (Sequence): Added a thread-safe, monotonically increasing sequence generator (Sequence.Create()) utilizing atomic interlocked instructions (Interlocked.Add) and volatile state memory management (Volatile.Read) for concurrent identifier numbering.
  • Human-Friendly Short Identifiers (ShortId): Implemented human-readable short token generation (ShortId.Generate()) built with an alphabet engineered specifically to omit visually ambiguous characters (such as I, l, 1, O, 0) to reduce transcription and manual entry errors.
  • ULID Generation (Ulid): Added foundational Universally Unique Lexicographically Sortable Identifier (ULID) generation support combining 48-bit millisecond timestamps with 80 bits of cryptographically secure randomness.

Changed

  • Internal Dependency Injection: Integrated all new string and sequence generation services with the internal dependency injection container (InternalContainer), standardizing instantiation across facades.

[2026-07-04]

Added — Dixor.Validation [v0.1.0] (Initial Release)

  • Email Validation Engine: Initial release of the state-machine email validation engine built without regular expressions to eliminate ReDoS vulnerabilities and reduce heap allocations.
  • Structured Diagnostics: Strongly typed error reporting (EmailValidationError) covering local-part syntax, domain labeling, consecutive dots, and illegal characters.
  • Suggestion Engine: Algorithmic domain correction engine that detects common mobile registration typos (e.g., suggesting gmail.com for inputs like gmai.com).
  • Parsing & Inspection: Dedicated APIs (EmailParser.Parse()) to safely extract and inspect structural email components (LocalPart, Domain).

Changed — Dixor.Identity [v0.1.4]

  • Architecture: Decoupled embedded Roslyn compile-time analyzers from the main Dixor.Identity runtime package. Analyzers will be distributed as an independent package to eliminate compiler tooling dependencies from the core runtime library.
  • Packaging: Reduced overall NuGet payload size by excluding analyzer binaries and updated package dependency metadata.

[2026-06-28] — Dixor.Identity [v0.1.1]

Added

  • UUIDv7 Engine: Implemented RFC 9562 compliant UUID Version 7 generation (Uuid7.New()).
  • Monotonic Generation: Added lock-free sequential generation (Uuid7.NewMonotonic()) for high-throughput sub-millisecond workloads.
  • Batch APIs: Added high-efficiency lazy batch generation (Uuid7.NewGuids(count)).
  • Inspection & Formatting: Added timestamp extraction (Uuid7.GetTimestamp()), parsing, validation, and domain prefix/suffix formatting (Uuid7.NewString()).
  • Roslyn Analyzers: Introduced diagnostic rule DIXOR001 to catch non-positive batch size parameters during compilation.
