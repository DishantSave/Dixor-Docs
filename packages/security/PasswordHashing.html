Password Hashing (PBKDF2-SHA256)

The IPasswordHasher provides cryptographically salted password hashing and timing-safe verification using PBKDF2 (Password-Based Key Derivation Function 2) with HMAC-SHA256.

Why Salted PBKDF2?

Plain hashes (such as SHA256("password")) are catastrophic for password storage:

  • No Salt: Two users with the same password have identical hashes.
  • Precomputed Rainbow Tables: Attackers can look up trillions of common password hashes in fractions of a second.
  • Too Fast: GPUs can calculate over 10 billion raw SHA-256 hashes per second.

Dixor.Security applies PBKDF2-HMAC-SHA256 with:

  1. 128-bit Random Salt: Generates a unique 16-byte cryptographically secure random salt for every password.
  2. 100,000 Iterations: Deliberately forces 100,000 computational rounds per attempt, slowing down brute-force attacks to a crawl while taking only ~10ms on server CPUs.
  3. Constant-Time Verification: Uses CryptographicOperations.FixedTimeEquals to prevent side-channel timing attacks.

Step-by-Step Implementation Guide

Step 1: Hashing a New Password on Registration

[ApiController]
[Route("api/account")]
public class AccountController(IPasswordHasher passwordHasher) : ControllerBase
{
    [HttpPost("register")]
    public async Task<IActionResult> Register([FromBody] RegisterDto dto)
    {
        // 1. Hash password with unique salt and 100,000 PBKDF2 rounds:
        string passwordHash = passwordHasher.HashPassword(dto.Password);

        // 2. Persist user with the password hash:
        var user = new User
        {
            Username = dto.Username,
            PasswordHash = passwordHash
        };

        // await db.Users.AddAsync(user);
        // await db.SaveChangesAsync();

        return Ok(new { Message = "User registered successfully." });
    }
}

The output string adheres to a self-contained portable format:

$dixor$pbkdf2$v1$iter=100000$g7E4k9...$X8b1m2...

Step 2: Verifying Passwords on Login

When a user logs in, verify their plaintext password against the stored hash:

[HttpPost("login")]
public async Task<IActionResult> Login([FromBody] LoginDto dto)
{
    // 1. Fetch user from database:
    // var user = await db.Users.FirstOrDefaultAsync(u => u.Username == dto.Username);
    // if (user == null) return Unauthorized();

    string storedHash = "$dixor$pbkdf2$v1$iter=100000$g7E4k9...$X8b1m2...";

    // 2. Verify password in constant time:
    bool isValid = passwordHasher.VerifyPassword(dto.Password, storedHash);

    if (!isValid)
    {
        return Unauthorized(new { Error = "Invalid username or password." });
    }

    // 3. Check for progressive rehash upgrade:
    if (passwordHasher.NeedsRehash(storedHash, targetIterations: 100_000))
    {
        // Re-hash with higher iterations and save:
        string upgradedHash = passwordHasher.HashPassword(dto.Password, iterations: 100_000);
        // user.PasswordHash = upgradedHash;
        // await db.SaveChangesAsync();
    }

    return Ok(new { Message = "Login successful." });
}

Hash Format Breakdown

$dixor $pbkdf2 $v1 $iter=100000 $g7E4k92A... $X8b1m2Q...
  [1]    [2]   [3]     [4]           [5]          [6]
  1. dixor: Library identifier prefix.
  2. pbkdf2: Underlying algorithm family.
  3. v1: Format schema version.
  4. iter=100000: Number of PBKDF2 iterations used to generate this specific hash.
  5. [5]: Base64-encoded 128-bit unique random salt.
  6. [6]: Base64-encoded 256-bit derived key hash.

Progressive Rehash Policy (NeedsRehash)

As hardware performance improves over the years, security guidelines increase recommended iteration counts. NeedsRehash allows you to seamlessly upgrade existing user hashes to higher iteration counts (e.g. from 50,000 to 150,000) whenever they log in, without resetting their passwords!
