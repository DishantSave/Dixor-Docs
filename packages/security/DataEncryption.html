Key-Based Data Encryption (AES-256-GCM AEAD)

The IDataEncryptor provides high-performance, authenticated symmetric encryption and decryption using NIST standard AES-256-GCM (Galois/Counter Mode) with Associated Data (AEAD).

Why AES-256-GCM AEAD?

Legacy symmetric ciphers—such as AES-CBC or unauthenticated AES-CTR—only provide confidentiality. They are vulnerable to:

  • Padding Oracle Attacks: Manipulating ciphertext padding bytes to leak plaintext.
  • Bit-Flipping Attacks: Modifying ciphertext bytes without detection.
  • Context Manipulation: Moving valid ciphertext from one tenant's database row to another.

AES-256-GCM solves all of these problems simultaneously:

  1. Confidentiality: 256-bit AES encryption in counter mode.
  2. Authenticity: A 128-bit GHASH authentication tag ensures the data has not been modified.
  3. Context Binding (AAD): Additional Authenticated Data ensures ciphertext cannot be transplanted to another user or tenant.

Step-by-Step Implementation Guide

Step 1: Encrypting Plaintext

[ApiController]
[Route("api/profiles")]
public class ProfileController(IDataEncryptor encryptor, IConfiguration config) : ControllerBase
{
    private readonly string _encryptionKey = config["Security:DataKey"] 
        ?? "MasterFieldLevelEncryptionSecretKey2026!";

    [HttpPost("save-ssn")]
    public IActionResult SaveSsn([FromBody] SsnUpdateRequest request)
    {
        string rawSsn = request.Ssn; // "123-45-6789"

        // Encrypt with AES-256-GCM, binding to tenant context via AAD:
        string encryptedSsn = encryptor.Encrypt(
            plaintext: rawSsn,
            secretKey: _encryptionKey,
            associatedData: $"Tenant:{request.TenantId}");

        // Save encryptedSsn to database (e.g. dx_enc_v3n8A...):
        // db.Users.Update(u => u.EncryptedSsn = encryptedSsn);

        return Ok(new { Status = "Saved", Ciphertext = encryptedSsn });
    }
}

The resulting string has the prefix dx_enc_:

dx_enc_j8A9Xm1...p7e3Q

Step 2: Decrypting Ciphertext

When reading encrypted fields from the database:

[HttpGet("view-ssn")]
public IActionResult GetSsn([FromQuery] string tenantId)
{
    string encryptedSsnFromDb = "dx_enc_j8A9Xm1...p7e3Q";

    // Decrypts and verifies the 128-bit authentication tag and AAD:
    string decryptedSsn = encryptor.Decrypt(
        ciphertext: encryptedSsnFromDb,
        secretKey: _encryptionKey,
        associatedData: $"Tenant:{tenantId}");

    return Ok(new { Ssn = decryptedSsn });
}
Warning

If an attacker attempts to decrypt with an incorrect associatedData (e.g. Tenant:tenant_evil), Decrypt throws a CryptographicException because the GHASH tag will not match.

Step 3: Non-Throwing TryDecrypt Pattern

In high-throughput services where malformed input might be supplied by clients, use TryDecrypt to avoid throwing exceptions:

if (encryptor.TryDecrypt(ciphertext, secretKey, out string? plaintext, out string? error, associatedData))
{
    Console.WriteLine($"Decrypted: {plaintext}");
}
else
{
    Console.WriteLine($"Decryption failed: {error}");
}

Step 4: Binary Byte Array Encryption (EncryptBytes / DecryptBytes)

When encrypting binary files, documents, or raw memory spans:

byte[] fileBytes = await File.ReadAllBytesAsync("sensitive-document.pdf");
byte[] raw32ByteKey = CryptographicUtils.GenerateSecureRandomBytes(32);

// Encrypt binary payload:
byte[] encryptedBytes = encryptor.EncryptBytes(fileBytes, raw32ByteKey);

// Decrypt binary payload:
byte[] originalBytes = encryptor.DecryptBytes(encryptedBytes, raw32ByteKey);

Universal Cross-Platform AEAD Architecture

In standard server and desktop environments, DataEncryptor uses NIST standard AES-256-GCM with hardware acceleration. However, on browser runtimes (such as Blazor WebAssembly), AesGcm.IsSupported is false.

To ensure seamless execution everywhere without throwing PlatformNotSupportedException, DataEncryptor provides a dual-mode universal AEAD engine:

Mode Marker Algorithm Engine Supported Environments Authentication Tag
0x01 (ModeGcm) AES-256-GCM Server, Desktop, Linux, macOS, Cloud (.NET 8/9/10) 128-bit GHASH tag
0x02 (ModeCbcHmac) AES-256-CBC + HMAC-SHA256 Browser WebAssembly, Mono, Fallback 128-bit Encrypt-then-MAC tag

Cryptographic Security Properties of WebAssembly Fallback

  • Encrypt-then-MAC: Plaintext is encrypted via AES-256-CBC with a cryptographically derived encryption key and a fresh 16-byte IV.
  • Separate Key Derivation: Distinct 256-bit encryption and authentication keys are derived using HMAC-SHA256 with domain-separated purposes.
  • Pre-Decryption Verification: The HMAC authentication tag is validated using constant-time comparison (CryptographicOperations.FixedTimeEquals) before any decryption occurs, preventing padding oracle attacks and timing leaks.

Wire Format

IDataEncryptor packages encrypted data into a compact, zero-overhead format:

[ dx_enc_ ] + Base64UrlEncode([ 1-byte Mode ][ IV / Nonce ][ 16-byte Auth Tag ][ Ciphertext ])
  • 1-byte Mode: 0x01 for AES-GCM or 0x02 for AES-CBC-HMAC.
  • 12 or 16-byte Nonce / IV: Fresh random initialization vector generated via RandomNumberGenerator.Fill on every call.
  • 16-byte Auth Tag: 128-bit authentication tag computed across ciphertext and associated data.
  • Ciphertext: Encrypted payload bytes.
