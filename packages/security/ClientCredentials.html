Client Credentials & Asymmetric Key Authentication

The IClientCredentialService provides comprehensive support for:

  1. API Client Credentials: Issuing high-entropy Client IDs and Client Secrets with salted PBKDF2-SHA256 hashing.
  2. Asymmetric Key Cryptography: Generating PEM-encoded RSA-2048, RSA-4096, and ECDSA NIST P-256 key pairs for digital signature creation and verification.

1. Client ID and Client Secret Authentication

In machine-to-machine (M2M) API architectures, external services authenticate using client credentials rather than human usernames and passwords.

Step 1: Provisioning Client Credentials

[ApiController]
[Route("api/admin/clients")]
public class ClientManagementController(IClientCredentialService credentialService) : ControllerBase
{
    [HttpPost("create")]
    public IActionResult CreateClient([FromQuery] string clientName)
    {
        // Generates ClientId (dx_client_...), PlaintextSecret (dx_sec_...), and HashedSecret
        ClientCredentials creds = credentialService.GenerateClientCredentials(
            prefix: "dx_client", 
            secretPrefix: "dx_sec");

        // 1. Save to Database: ONLY persist ClientId and HashedSecret!
        // db.Clients.Add(new ClientEntity { Id = creds.ClientId, SecretHash = creds.HashedSecret });
        // db.SaveChanges();

        // 2. Return PlaintextSecret to user ONCE:
        return Ok(new
        {
            ClientId = creds.ClientId,
            ClientSecret = creds.PlaintextSecret, // Never show again
            Warning = "Store this secret securely. It cannot be recovered."
        });
    }
}

Step 2: Validating Client Secrets at Runtime

When incoming requests provide client credentials in headers or basic auth, validate the secret using timing-safe PBKDF2 verification:

[HttpPost("api/v1/data-ingest")]
public IActionResult IngestData(
    [FromHeader(Name = "X-Client-Id")] string clientId,
    [FromHeader(Name = "X-Client-Secret")] string clientSecret)
{
    // 1. Fetch stored hash from database:
    // var client = db.Clients.FirstOrDefault(c => c.Id == clientId);
    // if (client == null) return Unauthorized();

    string storedHash = "$dixor$sec$v1$iter=100000$salt...$hash...";

    // 2. Verify secret using constant-time comparison:
    bool isValid = credentialService.ValidateSecret(clientSecret, storedHash);

    if (!isValid)
    {
        return Unauthorized(new { Error = "Invalid client credentials." });
    }

    return Ok(new { Status = "Authorized" });
}

2. Asymmetric Public/Private Key Authentication

For enterprise integration, webhook delivery, and banking APIs, asymmetric cryptography ensures that only the party holding the Private Key can sign payloads, while any party holding the Public Key can verify authenticity.

Step 1: Generating Key Pairs (PEM Format)

Generate standards-compliant RFC 7468 PEM key pairs:

// Generate RSA-2048 key pair
AsymmetricKeyPair rsaPair = credentialService.GenerateKeyPair(AsymmetricAlgorithmType.Rsa2048);

// Or generate high-performance ECDSA NIST P-256 key pair
AsymmetricKeyPair ecdsaPair = credentialService.GenerateKeyPair(AsymmetricAlgorithmType.EcdsaP256);

Console.WriteLine("Public Key (Distribute to verifiers):");
Console.WriteLine(rsaPair.PublicKeyPem);

Console.WriteLine("Private Key (Store securely in Key Vault):");
Console.WriteLine(rsaPair.PrivateKeyPem);

PEM Output Example:

-----BEGIN PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAyN8...
-----END PUBLIC KEY-----

-----BEGIN PRIVATE KEY-----
MIIEvgIBADANBgkqhkiG9w0BAQEFAASCBKgwggSkAgEAAoIB...
-----END PRIVATE KEY-----

Step 2: Signing Payloads with the Private Key

Before sending an outgoing webhook or transaction message, sign the payload:

public class WebhookSender(IClientCredentialService credentialService)
{
    public void SendWebhook(string payloadJson, string privateKeyPem)
    {
        // Computes SHA-256 digest and signs with private key:
        string signature = credentialService.SignData(
            data: payloadJson,
            privateKeyPem: privateKeyPem,
            algorithm: AsymmetricAlgorithmType.Rsa2048);

        // Send HTTP request with X-Signature header:
        // httpClient.DefaultRequestHeaders.Add("X-Signature", signature);
        // httpClient.PostAsync(url, new StringContent(payloadJson));
    }
}

Step 3: Verifying Signatures with the Public Key

When an incoming message arrives, verify that it was signed by the legitimate key holder:

[HttpPost("api/webhooks/receive")]
public async Task<IActionResult> ReceiveWebhook([FromHeader(Name = "X-Signature")] string signature)
{
    using var reader = new StreamReader(Request.Body);
    string payloadJson = await reader.ReadToEndAsync();

    string partnerPublicKeyPem = "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----";

    bool isAuthentic = credentialService.VerifySignature(
        data: payloadJson,
        signatureBase64: signature,
        publicKeyPem: partnerPublicKeyPem,
        algorithm: AsymmetricAlgorithmType.Rsa2048);

    if (!isAuthentic)
    {
        return BadRequest(new { Error = "Cryptographic signature verification failed. Message may have been forged." });
    }

    // Process trusted webhook payload...
    return Ok();
}
