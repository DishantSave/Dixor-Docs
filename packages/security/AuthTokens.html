Reversible Authentication Tokens

The IAuthTokenService provides a secure, reversible authentication token engine. It encrypts and packages user credentials—including Name, Password, and arbitrary Custom Data—into a compact, tamper-proof token that can be reverse-decoded and extracted by authorized backend services holding the application secret key.

Why Reversible Authenticated Tokens?

Traditional bearer tokens (like opaque tokens) require persistent session databases or Redis lookups for every API request. On the other hand, traditional signed tokens (like standard unencrypted JWTs) store payloads in readable Base64 format, exposing sensitive fields to anyone inspecting the token.

Dixor.Security solves both problems:

  1. Self-Contained & Reversible: Carries user identity, credentials, and custom metadata directly inside the token. No database lookup required.
  2. Confidential & Encrypted: Payloads are encrypted using AES-256 authenticated encryption (AEAD) via IDataEncryptor, supporting hardware AES-GCM and WebAssembly runtimes.
  3. Tamper-Proof Authenticity: Protected by a 128-bit cryptographic authentication tag. If the client modifies a single byte, decoding fails immediately.

Step-by-Step Implementation Guide

Step 1: Register in Program.cs

var builder = WebApplication.CreateBuilder(args);

// Registers IAuthTokenService and all security primitives
builder.Services.AddDixorSecurity();

// Or via 1-line ecosystem bootstrap:
// builder.Services.AddDixor();

var app = builder.Build();

Step 2: Generate an Authentication Token

Inject IAuthTokenService into your authentication endpoint or login controller:

[ApiController]
[Route("api/auth")]
public class AuthController(IAuthTokenService tokenService, IConfiguration config) : ControllerBase
{
    private readonly string _secretKey = config["Security:TokenSecret"] 
        ?? "MyEnterpriseSuperSecretKey2026!#$";

    [HttpPost("login")]
    public IActionResult Login([FromBody] LoginRequest request)
    {
        // 1. Verify user credentials against your identity store...

        // 2. Prepare custom data claims to embed into the token:
        var customData = new Dictionary<string, string>
        {
            ["TenantId"] = "tenant_enterprise_01",
            ["Role"] = "SystemAdministrator",
            ["Department"] = "Finance",
            ["Tier"] = "Enterprise"
        };

        // 3. Generate the reversible token (valid for 24 hours):
        string token = tokenService.CreateToken(
            name: request.Username,
            password: request.Password, // Safely encrypted via AES-256-GCM
            customData: customData,
            secretKey: _secretKey,
            lifetime: TimeSpan.FromHours(24));

        return Ok(new { AccessToken = token, TokenType = "DixorAuth" });
    }
}

The output is a URL-safe token with a dx_tok_ prefix:

dx_tok_gW8A1m9a2...B7e4xQ

Step 3: Reverse-Decode and Extract Data

When requests arrive at downstream APIs or background microservices, decode the token to extract the encapsulated credentials and metadata:

[ApiController]
[Route("api/orders")]
public class OrdersController(IAuthTokenService tokenService, IConfiguration config) : ControllerBase
{
    private readonly string _secretKey = config["Security:TokenSecret"]!;

    [HttpPost]
    public IActionResult CreateOrder([FromHeader(Name = "X-Auth-Token")] string token)
    {
        // 1. Decode and reverse-extract token info:
        AuthTokenDecodeResult result = tokenService.DecodeToken(token, _secretKey);

        if (!result.IsValid || result.Payload is null)
        {
            return Unauthorized(new { Error = result.Error ?? "Invalid or tampered token." });
        }

        // 2. Access extracted credentials:
        string username = result.Payload.Name!;
        string password = result.Payload.Password!;
        string tokenId = result.Payload.TokenId;
        DateTimeOffset expiresAt = result.Payload.ExpiresAt;

        // 3. Access extracted custom data:
        string tenantId = result.Payload.CustomData["TenantId"];
        string role = result.Payload.CustomData["Role"];

        // Process business logic with extracted credentials and claims...
        return Ok(new { Message = $"Order processed for user {username} under tenant {tenantId}." });
    }
}

Step 4: Safe Validation with TryDecodeToken

For performance-critical middleware pipelines, use the non-throwing TryDecodeToken pattern:

if (tokenService.TryDecodeToken(rawToken, secretKey, out var payload, out var error))
{
    // Token is authentic, unexpired, and decrypted:
    Console.WriteLine($"Authenticated: {payload.Name}, Role: {payload.CustomData["Role"]}");
}
else
{
    Console.WriteLine($"Rejected: {error}");
}

Token Structure & Wire Format

Under the hood, IAuthTokenService constructs a packed binary payload:

[ dx_tok_ ] + Base64UrlEncode([ 12-byte Nonce ][ 16-byte Auth Tag ][ Ciphertext ])
Component Size Purpose
dx_tok_ Prefix Identifies the token type for logging and telemetry.
Nonce 12 bytes (96 bits) Cryptographically secure random initialization vector generated per token. Prevents duplicate ciphertexts.
Tag 16 bytes (128 bits) AES-GCM GHASH authentication tag verifying that the token has not been tampered with.
Ciphertext Variable JSON payload of AuthTokenPayload encrypted with AES-256 counter mode.

Error Diagnostics

Result Property Scenario Recommended Action
IsValid == false, IsExpired == true Token exceeded its configured lifetime (ExpiresAt < UtcNow). Prompt client to re-authenticate or refresh token.
IsValid == false, Error contains "tampered" A single bit was modified or an incorrect secret key was provided. Reject request as unauthorized tampering attempt.
IsValid == false, Error contains "Base64Url" Token string was truncated or corrupted during transit. Return HTTP 400 Bad Request.
