Modular Dependency Injection (IDixorModule)

While declarative attributes handle individual service registrations, complex third-party configurations (e.g., configuring HttpClient, Entity Framework Core AddDbContext, RabbitMQ, Redis, or MediatR) often require programmatic setup.

Dixor.DI provides the IDixorModule interface for cleanly organizing these configurations.

Defining a Module

Implement IDixorModule in any class with a public parameterless constructor:

using Dixor.DI;
using Microsoft.Extensions.DependencyInjection;

public class PaymentIntegrationModule : IDixorModule
{
    public void ConfigureServices(IServiceCollection services)
    {
        services.AddHttpClient<StripePaymentClient>(client =>
        {
            client.BaseAddress = new Uri("https://api.stripe.com/v1/");
            client.Timeout = TimeSpan.FromSeconds(30);
        });

        services.AddHttpClient<PayPalClient>();
    }
}

Discovering and Executing Modules

In Program.cs, modules are discovered and invoked automatically:

1. Scan Calling Assembly

builder.Services.AddDixorModules();

2. Scan Target Assembly via Type Marker

builder.Services.AddDixorModulesFrom<PaymentIntegrationModule>();

3. Scan Explicit Assemblies

builder.Services.AddDixorModules(typeof(PaymentIntegrationModule).Assembly, typeof(CatalogModule).Assembly);

All discovered modules are instantiated and their ConfigureServices(services) method is called during container initialization.
