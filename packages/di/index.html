Dixor.DI Documentation

The Dixor.DI library simplifies dependency injection in modern .NET and ASP.NET Core applications by eliminating boilerplate container configuration in Program.cs.

Overview

Traditional .NET applications often accumulate hundreds of lines of repetitive service registrations:

builder.Services.AddSingleton<IEmailValidatorService, EmailValidatorService>();
builder.Services.AddScoped<IOrderRepository, OrderRepository>();
builder.Services.AddTransient<INotificationSender, NotificationSender>();
// ... dozens more

Dixor.DI transforms this model through declarative annotations, automatic assembly scanning, modular architecture, ambient context flow, external JSON/XML configuration, and single-line ecosystem bootstrapping:

// Program.cs - 1 line registers your entire application and Dixor ecosystem!
builder.Services.AddDixor();

Core Features

  • 1-Line Program.cs Setup: Register all application services, custom modules, and Dixor ecosystem services (Dixor.Identity + Dixor.Validation) in a single statement.
  • Declarative Attributes: Annotate classes with [Singleton], [Scoped], [Transient], or [Service] to declare lifetimes and interface bindings directly where classes are authored.
  • Auto-Discovery & Interface Mapping: Automatically binds classes to all implemented interfaces or an explicitly designated contract (As = typeof(...)).
  • Keyed Services Support: First-class support for keyed dependencies in .NET 8+ ([Service(Key = "primary")]).
  • Safe Conditional Registration (TryAdd): Prevent accidental overrides of custom mocks or existing services with TryAdd = true.
  • Multiple Implementations & Resolvers: Designate defaults with [PrimaryService], resolve keyed implementations with [FromKeyedServices], or dynamically select at runtime with IDixorResolver<TService>.
  • Ambient Context Flow: Pass cross-cutting request or tenant state down the call tree using DixorContext and IDixorContextAccessor<T> without polluting intermediate constructors.
  • Parameterized Activation (IDixorFactory<TService, TArg>): Combine DI container services with dynamic runtime arguments effortlessly.
  • External JSON & XML Bindings: Configure or swap service implementations from services.json, services.xml, or appsettings.json without recompiling code.
  • Modular Configuration (IDixorModule): Cleanly partition enterprise registrations across isolated module classes with parameterless discovery.
  • Ecosystem Integration: Seamlessly expose internal services from Dixor.Identity (UUIDv7, ULID, ShortId, NanoId, Base62, etc.) and Dixor.Validation (Email, Phone, Passport, Address, Aadhaar, Credit Card, URL) for direct constructor injection.
