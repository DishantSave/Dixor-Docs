External JSON and XML Dependency Bindings

In enterprise architectures, you often need to alter service registrations without recompiling application code:

  • Environment-Specific Providers: Swapping between AwsS3StorageProvider in production and LocalStorageProvider in local development.
  • Payment Gateways: Switching default payment processors (StripePaymentGateway vs PayPalPaymentGateway) based on region or regulatory requirements.
  • Test & CI/CD Pipelines: Replacing real email, SMS, and database services with mock or sandbox implementations without modifying C# source files.

Dixor.DI includes native support for external configuration-driven registrations via JSON, XML, and standard ASP.NET Core IConfiguration.

1. Registering via JSON File (AddDixorJson)

Step 1: Create services.json

Create a JSON file in your project:

{
  "Services": [
    {
      "Service": "MyApp.Services.IPaymentGateway, MyApp",
      "Implementation": "MyApp.Services.StripePaymentGateway, MyApp",
      "Lifetime": "Scoped",
      "Key": "stripe"
    },
    {
      "Service": "MyApp.Services.IPaymentGateway, MyApp",
      "Implementation": "MyApp.Services.PayPalPaymentGateway, MyApp",
      "Lifetime": "Scoped",
      "Key": "paypal"
    },
    {
      "Service": "MyApp.Services.INotificationService, MyApp",
      "Implementation": "MyApp.Services.SendGridEmailNotificationService, MyApp",
      "Lifetime": "Singleton",
      "TryAdd": true
    }
  ]
}

Ensure the file is copied to the build output in your .csproj:

<ItemGroup>
  <None Update="services.json">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
  </None>
</ItemGroup>

Step 2: Register in Program.cs

var builder = WebApplication.CreateBuilder(args);

// Register base Dixor DI
builder.Services.AddDixor();

// Load external bindings from services.json
builder.Services.AddDixorJson("services.json");

var app = builder.Build();

2. Registering via XML File (AddDixorXml)

Many legacy systems and enterprise integration pipelines rely on XML descriptor files. Dixor.DI natively parses and applies XML bindings without third-party dependencies.

Step 1: Create services.xml

<?xml version="1.0" encoding="utf-8" ?>
<Services>
  <Service Contract="MyApp.Services.IPaymentGateway, MyApp"
           Implementation="MyApp.Services.StripePaymentGateway, MyApp"
           Lifetime="Scoped"
           Key="stripe" />

  <Service Contract="MyApp.Services.IPaymentGateway, MyApp"
           Implementation="MyApp.Services.PayPalPaymentGateway, MyApp"
           Lifetime="Scoped"
           Key="paypal" />

  <Service Contract="MyApp.Services.IStorageProvider, MyApp"
           Implementation="MyApp.Services.AzureBlobStorageProvider, MyApp"
           Lifetime="Singleton"
           TryAdd="true" />
</Services>

Step 2: Register in Program.cs

// Load external bindings from services.xml
builder.Services.AddDixorXml("services.xml");

3. Registering via IConfiguration / appsettings.json

You can embed service registrations directly inside your application's appsettings.json or appsettings.{Environment}.json:

In appsettings.Production.json:

{
  "Logging": {
    "LogLevel": { "Default": "Information" }
  },
  "Services": [
    {
      "Service": "MyApp.Services.IStorageProvider, MyApp",
      "Implementation": "MyApp.Services.AwsS3StorageProvider, MyApp",
      "Lifetime": "Singleton"
    }
  ]
}

In appsettings.Development.json:

{
  "Services": [
    {
      "Service": "MyApp.Services.IStorageProvider, MyApp",
      "Implementation": "MyApp.Services.LocalStorageProvider, MyApp",
      "Lifetime": "Singleton"
    }
  ]
}

In Program.cs:

// Automatically binds the "Services" section from the active environment's configuration:
builder.Services.AddDixorConfiguration(builder.Configuration, sectionName: "Services");

Binding Configuration Schema Reference

Field (JSON) Attribute (XML) Type Required Description
Service / Contract Contract / Service string Yes Fully qualified or assembly-qualified interface or base class name.
Implementation Implementation string Yes Concrete implementation class name.
Lifetime Lifetime string No Container lifetime: Transient, Scoped, or Singleton (default: Scoped).
Key Key string No Optional key string for keyed service registration in .NET 8+.
TryAdd TryAdd boolean No If true, only registers the service if the contract has not already been registered.

Type Resolution Mechanics

Dixor.DI resolves type strings using intelligent assembly scanning:

  1. Assembly-Qualified Type Name (Recommended for external libraries): 
    "MyApp.Services.StripePaymentGateway, MyApp"
  2. Fully Qualified Namespace Name (Searches currently loaded assemblies): 
    "MyApp.Services.StripePaymentGateway"
  3. Simple Type Name (Searches loaded assemblies): 
    "StripePaymentGateway"

If a configured type cannot be resolved or does not implement the designated contract, Dixor.DI throws a descriptive InvalidOperationException at startup before the application begins accepting requests, ensuring configuration errors are caught immediately.

Overriding Code-Level Registrations

External configuration takes precedence when evaluated after code-level scanning:

// 1. Scans code attributes: registers DefaultPaymentGateway as IPaymentGateway
builder.Services.AddDixor();

// 2. Overrides default IPaymentGateway binding with PayPalPaymentGateway without code changes!
builder.Services.AddDixorJson($"services.{builder.Environment.EnvironmentName}.json");

This clean separation gives DevOps and platform engineers the flexibility to configure infrastructure dependencies dynamically per cluster or region.
